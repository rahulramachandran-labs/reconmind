# 0004. Postgres, with an append-only audit ledger enforced by a trigger

- Status: accepted
- Date: 2026-09-18

## Context

ReconMind makes claims about data and, later, records human decisions about those claims. Both need a history that can't be quietly edited, including by the application itself.

## Decision

- Postgres 16 for everything stateful: raw transactions, reference data, file loads, chat sessions, and later agent runs and LangGraph checkpoints. One database to back up and one connection string to configure.
- Schema changes go through Alembic, hand-written rather than autogenerated, because the ledger trigger is SQL that autogenerate can't see.
- `audit_ledger` gets `BEFORE UPDATE OR DELETE` (row) and `BEFORE TRUNCATE` (statement) triggers that raise. A wrong entry is fixed by appending a correcting entry that references the original.
- The raw `transactions` table keeps every contracted column nullable. The loader maps columns by name, and a batch that loses a column has to land visibly, not be rejected silently.

## Consequences

- The rule holds no matter which code path, script or person connects. A test proves it against a real Postgres.
- Dropping the table is still possible for an owner. The trigger guards history against application bugs and casual edits, not against a DBA.
- Tests need Postgres. CI runs it as a service; locally the database tests skip when none is reachable.
