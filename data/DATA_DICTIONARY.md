## transactions

One row per line item. Loaded from pipe-delimited submitter files in `data/sample/landing/`; the loader adds `submitter_file_name`.

| Column | Type | Description |
|---|---|---|
| `outlet_id` | text | Store id as sent by the submitter (OUT-NNNN). |
| `location_id` | text | Physical location (LOC-NNNN). The id to trust when it disagrees with outlet_id. |
| `transaction_id` | text | Submitter transaction id. Dedup key part 1. |
| `upc_code` | text | 12-digit UPC. Dedup key part 3. |
| `channel_basket_id` | text | Basket id (BSK-XXXXXXXX). Dedup key part 2. |
| `qty` | integer | Units, negative for returns. |
| `amount` | numeric(12,2) | Line amount after discounts. |
| `event_ts` | timestamptz | When the sale happened (UTC). |
| `submitter_file_name` | text | Source file, SUBMITTERID_YYYYMMDD_HHMM_NAME.txt. Added by the loader. |

Dedup key: `transaction_id`, `channel_basket_id`, `upc_code`. When a key appears in several files, the row from the file with the latest `YYYYMMDD_HHMM` in its name wins.

## Planted anomalies

### Key drift

`LOC-0517` reports under its canonical `OUT-1017` and under `OUT-1071`, which is not in `outlet_location_map`. Whole baskets drift together, as if some registers had the wrong store profile.

- Drifted rows: **251** of 8,373 deduplicated rows (3.0%).
- Detect: group by `location_id` per business date, flag more than one `outlet_id`, compare against the map.
- Expected: `key_drift` finding from the Reconciliation agent, severity S2.

### Duplicate submission

S1002 resent its 2026-06-12 file. `S1002_20260612_1120_ECOMM.txt` contains every key from `S1002_20260612_0304_ECOMM.txt`; 3 rows carry a corrected `qty` and `amount`. The resend landed after that night's DAG run, so dedupe never saw it.

- Duplicate keys: **88**, superseded rows: **88**, rows whose values changed: **3**.
- Detect: rank rows per dedup key by file timestamp; everything below rank 1 is superseded.
- Expected: `duplicate_submission` finding from the Reconciliation agent, severity S2.

### Schema drift

`S1003_20260616_0216_MOBILE.txt` (2026-06-16) renamed `channel_basket_id` to `basket_ref`. The loader maps by name, so its 82 rows land with a null `channel_basket_id`, and `validate_schema` fails that night with a `ContractViolation`.

- Detect: diff each batch header against the `raw.transactions` contract in the dbt manifest; confirm with the failed task log.
- Expected: `schema_drift` finding from the Data-Quality agent, severity S1 (a dedup-key column was lost).

### Volume anomaly

S1001's 2026-06-18 file `S1001_20260618_0638_POSFEED.txt` has 110 rows against a trailing 7-day average of 182.6 (40% below). It also landed 161 minutes after the submitter SLA, so the sensor waited.

- Detect: per-submitter daily row count against the trailing 7-day average; check sensor duration and landing time in the DAG history.
- Expected: `volume_anomaly` finding from the Data-Quality agent, severity S2.

## Not anomalies
